## Notes

- Correctness of the source change: I traced it and found no defect. In serve mode, `transform` no longer calls `buildIdForConfig`. The id is created lazily in `load` through `this.environment.getTopLevelConfig()`, so the client, the `ssr` runner, named environments, and non-runnable environments of one dev server all read the one value in `developmentBuildIds` (Risk 2). A configured `buildId` or `FOLDKIT_BUILD_ID` reaches `load` through `configuredBuildId`, so I2 holds in serve mode. In build mode, the literal path is byte-identical to the base, and nothing imports the virtual module (Risk 1, but see finding 2 about the test). The transformed `buildToken.js` content does not depend on the id (V3).
